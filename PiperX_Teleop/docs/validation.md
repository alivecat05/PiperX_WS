## 时间和动作

- 采集、反馈、命令统一用 `perf_counter()` 高精度单调时钟（Windows QPC），避免当前 Python `monotonic()` 的 15.6 ms 分辨率；不直接比较独立相机的 hardware clock。
- RealSense 支持时启用 Global Timestamp；`global_time` 和 `system_time` 均使用 SDK 帧时间映射到共同的单调时钟，避免用 Python 调度时间替代。原始硬件时钟的 `host_receive` 仅供预览，默认禁止用于录制。参见 [SDK 时钟域定义](https://realsenseai.github.io/librealsense/doxygen/rs__frame_8h_source.html) 和 [D555 DDS Global Timestamp 支持问题](https://github.com/realsenseai/librealsense/issues/14732)。`latency_ms` 可修正实测固定延迟。
- 默认 30 Hz 网格、等待 80 ms 后对齐；图像、命令和反馈所有来源时间戳的总跨度 ≤33.33 ms。联合匹配下一张未使用图像，避免独立最近邻重复选帧造成整组丢失。任何缺帧都使整段不完整，不会复制旧帧凑足 30 FPS。
- `action` 是观测时刻之前最后一条由 SDK 发送的目标，包含限速/限幅结果；不是手柄原始位姿，也不保证机器人已到达。
- 两臂 CAN 顺序发送，各自记录发送完成时间；没有双臂总线原子发送保证。
- 来源时间戳、实际关节反馈和配置保存在原始 episode 中；LeRobot 以连续 grid 构建均匀时间轴。
- 当前保留的是对齐后图像及来源元数据，不保留所有未匹配原始帧。
- A 固定录制结束时刻；继续对齐截止前的尾帧，再由后台线程完成写盘。`SAVING` 期间遥操和断联检查继续运行；保存完成后可开始下一段。
- 就绪检查要求三路 RGB、两臂反馈和 Quest 跟踪均有效；RGB 默认超过 250 ms 没更新即停止遥操。双臂反馈仍新鲜时进入原位保持恢复，结束采集、取消复位，不发送阻尼下沉的电子急停；相机恢复后仍需显式恢复，不自动续动。机械臂反馈同时丢失时不能使用旧反馈保持，仍执行硬故障保护。复位中再次按 Y，用实际关节位置替换剩余路径。
- 位姿取最新帧；四个面键的按下/释放逐一编号、排队，收到处理确认前重发，已处理事件去重。断联不重放操作，过期事件停止控制。确认编号表示处理完毕；具体执行/拒绝结果通过编号通知返回。
- XR 每个可发送帧推送输入，移除会将 90 Hz 降成 45 Hz 的 15 ms 门槛。60 Hz 控制循环默认关闭额外低通，采用 1 mm/0.5° 连续死区；可选 `pose_smoothing_s` 会增加延迟。跟随限速调整为 0.5 m/s、2 rad/s，SDK 运行速度 100%，保留工作空间、跟踪跳变和位置跟踪误差保护，复位速度仍为 10%。窗口提供每臂跟踪误差、命令年龄、触及限速标记。日志曾记录 `position_emulated`、`controller_missing` 等追踪中断，需保证 Quest 能持续看到手柄；这些变化针对软件输入抖动和追赶滞后，机械臂实际响应须实机复测。
- Y 复位同一控制 tick 下发左右首航点，各自推进、检查到位和超时；两臂全部完成后结束。CAN 仍是逐条发送，不保证同微秒到达。再次按 Y 同时用测量关节位置保持两臂。
- 正常退出先保持新鲜测量位姿、已使能夹爪宽度，再断开 CAN，保留使能；故障或无法安全保持时仍急停。
- 目标越限（状态 4、err_code=0）与软件跟踪误差进入 recovery，请求测量关节保持并持续读反馈，不自动急停或 reset。确认条件包含新鲜反馈、NORMAL、全部关节使能、MOVE J、位置接近保持目标及静止 0.2 秒；未满足时明确显示尚未确认，不宣称机械锁死。示教使用本体按钮，示教期间不发送运动指令；退出后由新长按 Y 或电脑 R 显式恢复，不能自动重放旧目标。通信/电机硬故障仍保留故障保护。实际控制器能否接受越限后的保持以及示教无缝恢复，尚未完成实机验证。
- 正常松开时，action 保留松开前最后成功下发的滤波 TCP 目标，食指夹爪独立。重新按住时以实际反馈建立新起点。断联、追踪丢失、故障和退出保持继续使用各自保护逻辑。
- 新录制为三路 MP4、action.csv、samples.jsonl，统一 Unix 秒，逐帧索引一致。action 保留遥操发送目标语义，与 PiperCapture 的下一时刻测量 action 区分；导出兼容旧 JPEG v1 和新 MP4 v2。
- 声音在独立线程播放，故障优先；手柄震动按通知编号去重。状态每 30 ms 推送，未收到新手柄输入时也能报告故障；只有写盘提交成功后才发“保存完成”。

## 实机前需配置

- D555 的 PoE、DDS 发现、Windows 防火墙与 SDK/固件配套；依据 `discover` 选择真实支持的 RGB 模式。
- 两臂 CAN 对应关系、固件 profile、TCP 标定、坐标方向与空间范围。
- 复位路径必须适合当前安装；依次执行左臂/右臂关节路径并等待反馈确认；不生成避障轨迹。
- 手柄保存初始位只替换各臂路径的最后一个路点；已有中间路点仍需确认适配新初始位。
- 当前只有单臂空间/速度限制，未实现双臂碰撞检测。首次联调须小范围、低速，保留物理急停。
- SDK `reset()` 是控制器状态复位，不是回初始位姿；本项目回位调用 `move_j()`。
